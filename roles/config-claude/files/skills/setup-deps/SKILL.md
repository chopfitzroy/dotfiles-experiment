# /setup-deps

Set up local dependency source cloning for this project.

## Purpose

This skill helps developers clone git repositories for their dependencies (source, docs, examples, etc.) so that Claude Code can read them locally instead of fetching from the web. This is especially useful for poorly-documented packages where reading source code is necessary.

## How It Works

1. **Detect package ecosystems** in the current project
2. **Parse dependencies** from package manifests
3. **Cross-reference** against a curated registry of "source-helpful" packages
4. **Present suggestions** to the user with rationales
5. **Prompt for custom additions** (packages not in registry)
6. **Generate files**: setup script, .gitignore entry, CLAUDE.md section
7. **Offer to run** the setup script and add package manager hooks

## Supported Ecosystems

- **Node.js**: package.json
- **PHP**: composer.json
- **Rust**: Cargo.toml
- **Python**: pyproject.toml, requirements.txt
- **Go**: go.mod
- **Ruby**: Gemfile

## Registry

The registry is located at `~/.claude/skills/setup-deps/registry.ts`. It maps package names to git repositories with multiple resources per package (source, docs, examples, etc.).

## Behavior

### Step 1: Detect Ecosystems

Look for package files in the current directory:
- package.json (Node.js)
- composer.json (PHP)
- Cargo.toml (Rust)
- pyproject.toml or requirements.txt (Python)
- go.mod (Go)
- Gemfile (Ruby)

If none found, inform the user and exit.

### Step 2: Parse Dependencies

For each detected ecosystem, extract dependency names:
- **Node.js**: Read `dependencies` and `devDependencies` from package.json
- **PHP**: Read `require` and `require-dev` from composer.json
- **Rust**: Read `[dependencies]` from Cargo.toml
- **Python**: Read dependencies from pyproject.toml or requirements.txt
- **Go**: Read `require` from go.mod
- **Ruby**: Parse Gemfile for gem declarations

### Step 3: Match Against Registry

Read the registry file and find matches:
1. Load `~/.claude/skills/setup-deps/registry.ts`
2. For each dependency, check if it matches any registry entry
3. Support glob patterns (e.g., `@effect/*` matches `@effect/schema`)
4. Collect all matching packages and their resources

### Step 4: Present Suggestions

Show a table of matches:

```
Found X packages with recommended resources:

| Package | Resource | Repository | Why |
|---------|----------|------------|-----|
| effect | source | github.com/Effect-TS/effect | Complex API, docs focus on concepts |
| effect | docs | github.com/Effect-TS/website | Documentation source with examples |
| zod | source | github.com/colinhacks/zod | Advanced inference patterns |
```

Ask: "Would you like me to set up local source cloning for these?"

If user says no or cancels, exit.

### Step 5: Prompt for Custom Additions

After user confirms, ask:

"Any other packages/resources to add? (format: package resource url)"

Examples:
- `hono source https://github.com/honojs/hono`
- `my-lib docs https://github.com/company/my-lib-docs`

User can provide multiple entries or say "no"/"skip".

Parse each entry as: `<package-name> <resource-name> <git-url>`

### Step 6: Generate Files

#### A. scripts/setup-deps.sh

Create (or overwrite) `scripts/setup-deps.sh`:

```bash
#!/bin/bash
# scripts/setup-deps.sh
# Auto-generated by /setup-deps skill

set -e

DEPS_DIR=".deps"

add_resource() {
  local package="$1"
  local resource="$2"
  local repo="$3"
  local target="$DEPS_DIR/$package/$resource"

  if [ ! -d "$target" ]; then
    echo "Cloning $package/$resource..."
    mkdir -p "$DEPS_DIR/$package"
    git clone --depth 1 "$repo" "$target"
  else
    echo "$package/$resource already exists, skipping"
  fi
}

# <generate add_resource calls for each package/resource>

echo "Done! Dependencies cloned to $DEPS_DIR/"
```

Make it executable: `chmod +x scripts/setup-deps.sh`

#### B. .gitignore

If `.gitignore` exists, check if `.deps/` is already in it.
If not, append:

```gitignore
# Local dependency sources (managed by setup-deps.sh)
.deps/
```

If `.gitignore` doesn't exist, create it with the above content.

#### C. CLAUDE.md

If `CLAUDE.md` doesn't exist, create it with:

```markdown
## Local Dependency Sources

The `.deps/` directory contains cloned source code for dependencies.

Structure: `.deps/<package>/<resource>/` (e.g., `.deps/effect/source/`, `.deps/effect/docs/`)

When investigating package internals or undocumented behavior, check `.deps/` first.

To populate/update: `./scripts/setup-deps.sh`
```

If `CLAUDE.md` exists but doesn't have a "Local Dependency Sources" section, append the above.

If it already has the section, leave it unchanged.

### Step 7: Offer to Run Setup

After files are generated, inform the user:

```
Created:
- scripts/setup-deps.sh (clone script for X resources)
- Updated .gitignore (added .deps/)
- Updated CLAUDE.md (added Local Dependency Sources section)
```

Then ask:

"Would you like me to:
1. Run the setup script now?
2. Add a postinstall hook to package.json?"

#### Running the Script

If user agrees to (1), run: `./scripts/setup-deps.sh`

Show the output and list what was cloned.

#### Adding Postinstall Hook

If user agrees to (2) and this is a Node.js project:

Read `package.json`, add or update the `postinstall` script:

```json
{
  "scripts": {
    "postinstall": "./scripts/setup-deps.sh"
  }
}
```

If a postinstall script already exists, warn the user and ask if they want to replace it or chain the commands.

For other ecosystems, skip this step (can be added in future).

## Important Notes

- User can manually edit `scripts/setup-deps.sh` later to add more resources
- The `add_resource` function is idempotent - safe to run multiple times
- Large repos use `--depth 1` to minimize disk usage
- CLAUDE.md is intentionally generic (doesn't list all packages) so it doesn't need updating when packages change

## Error Handling

- If git is not installed, inform user and exit
- If a repository URL is invalid, show the error and continue with other repos
- If scripts/ directory doesn't exist, create it
- If permission errors occur when writing files, inform user
